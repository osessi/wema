# 0008 · RGPD : export, suppression avec délai de grâce, purge réglementaire, consentement parental

- **Date :** 2026-11-03
- **Statut :** proposé (à valider par Olivier, et par un juriste pour les textes et les durées)

## Contexte

Wema traite des données de mineurs, dont des données de santé (fiche 0006). Il faut permettre l'exercice des droits (accès, portabilité, effacement), fixer des durées de conservation, recueillir le consentement parental et faire accepter des conditions versionnées. Le journal d'apprentissage est en ajout seul (fiche 0002, AGENTS.md règle 3) : la seule exception admise est la purge réglementaire.

## Décision

### Purge réglementaire

- Les déclencheurs « ajout seul » (`learning_events`, `tutor_messages`, `exercise_variants`, `exercise_attempts`, `ai_calls`) laissent passer un **DELETE** seulement si le réglage local à la transaction `wema.regulatory_purge` vaut `on` (migration 0018). `UPDATE` et `TRUNCATE` restent interdits dans tous les cas ; le journal d'audit n'est jamais effaçable.
- Ce réglage n'est posé que par `@wema/db` (`purgeUser`, `runRetention`), dans une transaction : il disparaît à la fin de celle-ci. Des tests prouvent qu'une suppression ordinaire reste refusée, avant comme après une purge.
- Ce n'est pas une barrière de sécurité contre un accès SQL direct (qui peut poser le réglage) : c'est une garde contre l'erreur de code. La sécurité vient des droits sur la base.

### Suppression d'un compte

- Demandée depuis « Mon compte » ; pour un élève suivi par un parent (ou un compte élève géré sans e-mail ni téléphone), c'est le **parent** qui la demande. Le dernier super admin ne peut pas se supprimer ; un parent supprime d'abord les comptes d'enfants qu'il a créés.
- **Délai de grâce** réglable (30 jours par défaut) pendant lequel la demande s'annule ; le compte reste utilisable.
- À l'échéance, la tâche « conservation » purge : apprentissage, conversations, variantes, relances, besoins déclarés, liens, messages et fils directs, notifications, jetons push, séances d'agenda, moyens de connexion, sessions. La ligne `users` reste, **anonyme** (« Compte supprimé », `purged_at`) : les références (audit, exercices écrits par un prof, coûts d'IA, paiements gardés pour la comptabilité) restent valides sans désigner personne.
- Trace d'audit `account.purge` : identifiant et nombres de lignes seulement.

### Durées de conservation

Réglages `privacy` dans le back-office (`/admin/reglages`), tâche quotidienne `conservation` : sessions expirées, codes à usage unique (1 jour après expiration), journal d'appels d'IA (365 jours), journal des envois terminés (90 jours), conversations du prof IA (non limitées par défaut), comptes sans connexion depuis 730 jours (suppression programmée avec le délai de grâce, annulée par une connexion ; l'équipe Wema est exclue). `users.last_seen_at` est noté au plus une fois par heure.

### Consentement parental et conditions

- `parental_consents` (élève, parent, méthode, versions, date). Recueilli quand un parent crée lui-même le lien parent-enfant, ou explicitement depuis « Mon compte » (case à cocher). Un lien créé par un tiers ne vaut pas consentement.
- L'espace école signale les comptes élèves créés par l'école sans consentement enregistré.
- Inscription seule : année de naissance déclarée, **non conservée** ; sous l'âge du consentement numérique (réglable, 15 par défaut, dépend du pays), refus : le parent crée le compte.
- `terms_acceptances` : les versions en vigueur des conditions et de la politique sont dans les réglages ; tant qu'un utilisateur n'a pas accepté la version courante, les espaces le renvoient vers `/compte/conditions`.

### Export

`GET /api/account/export` (et `/api/account/children/:id/export` pour un parent) : JSON complet sans aucun secret, y compris le journal, le profil explicable et les besoins déclarés déchiffrés (la personne concernée ou son parent y ont droit).

## Conséquences

- Les textes légaux (`/mentions-legales`, `/confidentialite`, `/conditions`, `/cookies`) sont une base à faire valider par un juriste ; les champs de l'éditeur sont à compléter.
- Une nouvelle table contenant des données personnelles doit être ajoutée à la purge (`OPTIONAL_PURGE_STEPS` ou `purgeUser`) et à l'export.
- Les paiements ne sont pas purgés (obligation comptable) ; un abonnement en cours n'est pas résilié automatiquement par la suppression : à traiter avec la facturation.
- Pas d'envoi d'avertissement avant la suppression d'un compte inactif tant que les notifications ne le prévoient pas.
